Types, multiple dispatch, and automatic differentiation

Tech Tacos · 71-North studio · Tuesday, October 20, 2026, 5:00 pm · Dr. Nathan Krislock

Today we build two new kinds of numbers in a few lines each: integers mod $p$, and dual numbers that compute derivatives. Then we combine them without writing any new code. All you need is the Julia REPL and one small package.

0. REPL tips

  • Start Julia by typing julia in a terminal, or open the Julia app.
  • Type ? for help mode, ] for package mode, and Backspace to go back.
  • Unicode: type \varepsilon then press Tab to get ε.
  • methods(f) lists all the methods of a function f. @which f(x) shows which method Julia picks.

1. Multiple dispatch in one minute

A Julia function can have many methods. Julia picks the most specific method based on the types of all the arguments.

describe(x)          = "something"
describe(x::Number)  = "a number"
describe(x::Integer) = "an integer"
describe(x::String)  = "a string"

describe(1), describe(1.5), describe("hi"), describe([1, 2])
# ("an integer", "a number", "a string", "something")

methods(+)           # + itself has around 200 methods

Arithmetic such as + and * is just ordinary functions with many methods. We can add our own.

2. Integers mod $p$

The integers mod a prime $p$ form a field $\mathbb{Z}_p$: we can add, subtract, multiply, and divide by anything nonzero. We put $p$ in the type, so Mod{7} and Mod{11} are different types.

Installing a package

Julia has thousands of free packages. You can browse them at juliapackages.com. We need one, Primes.jl, for its isprime function. At the julia> prompt, press ] to enter package mode. The prompt changes to (@v1.13) pkg>. Type add Primes, then press Backspace to go back.

] add Primes              # one time only; the first add can take a minute
using Primes              # load it in each new session
isprime(7), isprime(91)   # (true, false)   91 = 7 × 13

The type

struct Mod{p} <: Integer
    k::Int
    function Mod{p}(k) where p
        @assert isprime(p)
        new(mod(k, p))
    end
end

import Base: +, -, *, /, inv, show, promote_rule, oneunit, abs, rand

show(io::IO, a::Mod{p}) where p =
    print(io, get(io, :compact, false) ? a.k : "$(a.k) (mod $p)")

+(a::Mod{p}, b::Mod{p}) where p = Mod{p}(a.k + b.k)
-(a::Mod{p}) where p = Mod{p}(-a.k)
-(a::Mod{p}, b::Mod{p}) where p = a + -b
*(a::Mod{p}, b::Mod{p}) where p = Mod{p}(a.k * b.k)
inv(a::Mod{p}) where p = Mod{p}(invmod(a.k, p))
/(a::Mod{p}, b::Mod{p}) where p = a * inv(b)

promote_rule(::Type{Mod{p}}, ::Type{Int}) where p = Mod{p}   # Mod + Int gives Mod
oneunit(::Type{Mod{p}}) where p = Mod{p}(1)
abs(a::Mod{p}) where p = a.k        # used by \ to choose pivots

rand(::Type{Mod{p}}, d::Integer, dims::Integer...) where p =
    Mod{p}.(rand(0:p-1, d, dims...))

Try it

a = Mod{7}(3)
b = Mod{7}(5)
a + b        # 1 (mod 7)
a * b        # 1 (mod 7)
inv(a)       # 5 (mod 7)
a / b        # 2 (mod 7)
a + 10       # 6 (mod 7)   promotion at work
a^100        # 4 (mod 7)   we never wrote ^ ; Julia's generic power code works

Linear algebra over $\mathbb{Z}_7$, for free

A = Mod{7}.([2 1 0; 1 3 1; 0 1 4])
b = Mod{7}.([1, 2, 3])
x = A \ b    # Julia's generic LU solver, run in mod-7 arithmetic
A * x == b   # true

Ainv = inv(A)   # [1 6 2; 6 2 3; 2 3 3], the inverse mod 7
A * Ainv        # the identity matrix, mod 7

B = rand(Mod{7}, 4, 4)   # a random matrix (singular about 16% of the time)

Nobody who wrote Julia's \ knew about our Mod type. It works because the solver only needs +, -, *, /, and a way to pick pivots, and we supplied those.

3. Automatic differentiation with dual numbers

A dual number is $a + b\varepsilon$, where $\varepsilon^2 = 0$. Expanding gives

$$ f(a + b\varepsilon) = f(a) + b\,f'(a)\,\varepsilon . $$

So if we evaluate $f$ at $a + \varepsilon$, the $\varepsilon$ part of the answer is $f'(a)$. The rules below are the sum, product, and quotient rules from calculus.

struct Dual{T<:Real} <: Number
    p::T     # value
    d::T     # derivative
end
Dual(p, d) = Dual(promote(p, d)...)

import Base: +, -, *, /, inv, sin, cos, exp, show, promote_rule, convert

+(x::Dual, y::Dual) = Dual(x.p + y.p, x.d + y.d)              # sum rule
-(y::Dual)          = Dual(-y.p, -y.d)
-(x::Dual, y::Dual) = x + -y
*(x::Dual, y::Dual) = Dual(x.p * y.p, x.d * y.p + x.p * y.d)  # product rule
inv(y::Dual)        = Dual(1 / y.p, -y.d / y.p^2)
/(x::Dual, y::Dual) = x * inv(y)                               # quotient rule

sin(y::Dual) = Dual(sin(y.p),  cos(y.p) * y.d)                 # chain rule
cos(y::Dual) = Dual(cos(y.p), -sin(y.p) * y.d)
exp(y::Dual) = Dual(exp(y.p),  exp(y.p) * y.d)

promote_rule(::Type{Dual{T}}, ::Type{S}) where {T<:Real, S<:Real} =
    Dual{promote_type(T, S)}
convert(::Type{Dual{T}}, x::Real) where T<:Real = Dual{T}(x, zero(T))
convert(::Type{Dual{T}}, x::Dual) where T<:Real = Dual{T}(x.p, x.d)

show(io::IO, x::Dual) = print(io, x.p, " + ", x.d, "*ε")

ε = Dual(0, 1)

Try it

ε * ε                        # 0 + 0*ε
f(x)  = sin(exp(x + 1))
fp(x) = cos(exp(x + 1)) * exp(x + 1)    # derivative by hand

f(4.0), fp(4.0)              # (-0.6876914116945115, -107.74841574308525)
f(4.0 + ε)                   # -0.6876914116945115 + -107.74841574308525*ε

It even works through loops

The Babylonian method computes $\sqrt{x}$ by repeating $t \leftarrow (t + x/t)/2$. We never tell it about derivatives.

function babylonian(x; N = 10)
    t = (1 + x) / 2
    for i in 2:N
        t = (t + x / t) / 2
    end
    return t
end

babylonian(2.0 + ε)          # 1.41421356237... + 0.35355339059...*ε
sqrt(2), 1 / (2sqrt(2))      # check: √2 and d/dx √x at x = 2

Bonus: the derivative of $\log\det X$

Here is a fact most people have not seen. For an invertible matrix $X$,

$$ \frac{\partial}{\partial x_{ij}} \log\det X = (X^{-1})_{ji}. $$

Why: expanding the determinant along row $i$ shows that $\partial \det X / \partial x_{ij} = C_{ij}$, the $(i,j)$ cofactor. Also $X^{-1} = C^{T} / \det X$. So $\partial \log\det X / \partial x_{ij} = C_{ij} / \det X = (X^{-1})_{ji}$.

Let us check it with dual numbers. We nudge one entry of $X$ by $\varepsilon$ and call Julia's own det. We need three small additions: a rule for log, and two methods that let Julia's LU code pivot on dual numbers.

using LinearAlgebra

Base.log(x::Dual) = Dual(log(x.p), x.d / x.p)
Base.abs(x::Dual) = abs(x.p)    # LU pivots on the value part
Base.oneunit(::Type{Dual{T}}) where T = Dual{T}(oneunit(T), zero(T))

X = [4.0 1 2; 0 3 1; 1 0 5]
D = Dual.(X, 0.0)        # X with zero ε parts
D[1, 2] += ε             # nudge the (1,2) entry
log(det(D))              # 4.00733... + 0.0181818...*ε
inv(X)[2, 1]             # 0.0181818...  (it is 1/55)

Note the swapped indices: nudging entry $(1,2)$ gives entry $(2,1)$ of the inverse. As a sanity check, nudge by a small real number instead:

t = 1e-6
E = zeros(3, 3); E[1, 2] = 1
(log(det(X + t*E)) - log(det(X))) / t    # about 0.0181818, close but not exact

Each dual-number pass gives one partial derivative, because $\varepsilon$ sits in one entry. This is forward-mode AD. Getting the whole gradient in one pass takes reverse-mode AD, which is what machine learning libraries use.

4. If time allows: why not just use $(f(x+h) - f(x))/h$?

The finite difference $\dfrac{f(x+h) - f(x)}{h}$ gets closer to $f'(x)$ as $h$ shrinks, but only up to a point. When $h$ is tiny, $f(x+h)$ and $f(x)$ agree in almost every digit, and subtracting them throws those digits away. This is called catastrophic cancellation.

fd(f, x, h) = (f(x + h) - f(x)) / h   # f is sin(exp(x + 1)) from section 3

f(4.0 + ε)               # dual numbers: -107.74841574308525 in the ε part
fp(4.0)                  # hand-written derivative: the same number

for k in 1:16
    h = 10.0^(-k)
    err = abs(fd(f, 4.0, h) - fp(4.0))
    println("h = 1e-", k, "    error = ", err)
end
# the error is smallest near h = 1e-9 (about 4e-6), then grows again;
# at h = 1e-16, 4.0 + h == 4.0 in floating point, so the error is the whole
# derivative, about 108

Dual numbers never subtract nearly equal numbers to get the derivative, so there is no $h$ to choose and no cancellation. The answer is as accurate as $f$ itself.

The takeaway

We wrote two small types. We did not write a linear solver, a matrix inverse, a power function, or a determinant rule for derivatives. Julia's generic code and our types work together because methods are chosen by the types of all the arguments. That is multiple dispatch.

Where to go next: juliapackages.com. For real work, ForwardDiff.jl is a full version of our Dual type, and Zygote.jl and Enzyme.jl do reverse-mode AD.
